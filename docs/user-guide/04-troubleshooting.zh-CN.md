# 问题处理

先原则：**不要用一个笼统的“再试一次”覆盖所有问题**。下面按实际症状处理；任何“未知”都保留现场，不要反复提交同一命令。

## 页面打不开 / 会话失效

1. 终端看 `pnpm start` 是否仍在运行；地址与终端打印的一致。
2. `pnpm doctor` 查看实例、端口、锁与配置诊断。
3. 页面提示需要会话：按提示重新建立；不要从别人的 state 目录复制凭据。
4. 端口被占用：换 `--port`/`--api-port`，不要杀掉不认识的进程。

## “对话模型：未配置 / 服务异常”

- 打开模型设置，确认已选择模型且配置有效；首次保存不会发送请求。
- “服务异常”通常是 provider 返回错误或网络问题：核对 endpoint/key 后重试一条普通消息。
- 不要因此启用固定流程来“绕过”；固定流程不会调用真实模型。
- 模型离线时已有问题/工作仍可处理；新回复不可用是预期行为。

## “开发执行：暂不可用”

状态条或执行器视图会给出原因：

| 显示 | 含义 | 建议 |
| --- | --- | --- |
| 未安装 Codex | 本机没有可用执行器 | 按分发指南安装；不要手改准入标记 |
| 版本不匹配/尚未验证 | 版本未通过准入 | 使用已验证版本；不要复制他人的 profile |
| 当前平台尚未通过验证 | 平台不在受控范围 | 继续用对话/审阅；不要声称已支持 |
| 需要重新认证 | 原生账号/认证失效 | 在原执行器侧重新登录，再刷新 |
| 策略未准备/暂不可调度 | 项目或策略不允许 | 在项目设置/委托确认页核对范围与验收标准 |
| 只读恢复 | 当前是恢复只读 | 只审阅；新的执行需要正常启动与明确授权 |
| 未知 | 没有观察到状态 | 先“检查执行器”，不要当作正常 |

执行器目录里的“已准入”只说明该 profile 可派工，不表示所有操作、平台或版本都已认证。

## “需要项目 / 还没有项目”

先导入一个本地 Git 仓库（见 [项目与主对话](02-projects-and-conversation.zh-CN.md)）。没有项目时普通对话仍可用。

## “只读恢复”

- 这是启动方式决定的，不是 bug；不能通过刷新、重试或改页面状态解除。
- 不要删除 restore marker、复制旧数据库或强行切换数据库来“恢复”。
- 需要新的执行：停止当前实例，按正常（非恢复）方式重新启动并重新确认授权。

## 等待或网络中断

- 发送后网络丢响应：使用页面提供的“核对原请求”/刷新恢复，不要另发一条相同请求。
- 原结果未知时保持未知；系统不会自动重发或自动换模型。
- 刷新后草稿与既有工作保留；正在流式显示的回复会从已保存部分恢复。

## “试用准备”读取失败、未提供或指标被隐藏

- 红条 + “重试”只会重新读取状态（并让工作台刷新配置）；不会发送命令或模型请求。
- “当前服务未提供试用状态接口”表示后端版本较旧：继续使用既有视图，不会把旧观察当作当前状态。
- 页面显示“未观察”时不要按“正常”处理。
- 观察区显示“缺少观测范围/窗口/覆盖说明”或“不包含当前项目”：这是有意的保护，不是页面坏了；当前产品默认也不传 G 指标。不要要求页面显示未声明的统计。
- 观察区显示“样本不足”或“未知”：不要把它读成 0 或效率提升。

## 当前项目/会话看起来不对

- 试用准备显示的是左侧项目筛选与当前会话，不提供切换；请先在左侧选择项目/后选择对话，再回到试用准备核对。
- 项目行没有“当前”标记且显示“全部项目”，表示当前筛选是“全部项目”，不是缺失。

## 长项目名、窄屏、键盘

- 项目名过长会在自身区域换行/截断；若出现横向滚动或按钮被遮挡，记录浏览器宽度与状态，交回 F/main。
- 手机端“工作空间/工作详情”互斥；用关闭按钮、遮罩或 Escape 退出。
- 纯键盘操作：Tab 可达刷新与动作；焦点应可见。若不可达，记录页面与动作名称。

## 什么时候停下来上报

出现以下任一情况，保留现场并上报，不要继续尝试：

- 页面显示未知写入者/不确定状态；
- 同一操作多次“未知”；
- 需要删除/迁移数据或修改凭据；
- 任何看起来像授权绕过或跨账号访问的现象。

上报时提供：启动命令（不含凭据）、页面地址、状态条文字、时间、`reports/trial-experience/wave25-status.json` 中注明的范围，以及可复现步骤。
