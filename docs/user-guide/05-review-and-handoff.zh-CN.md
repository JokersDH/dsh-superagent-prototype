# 交付审阅与交接

## 1. 审阅一次交付

1. 打开“工作与交付”，选择当前工作；右侧详情显示目标、合同、检查与产物。
2. 看阶段条：已委托 → 执行 → 验证 → 交付。当前阶段有真实投影；不要用颜色自己推进度。
3. 验证结果可能为 PASS/FAIL/SKIPPED/NOT_TESTED。**NOT_TESTED 不是通过**；FAIL 不能接受。
4. 候选人必须属于当前 assignment，且验证为当前版本；过期候选会明确拒绝。
5. 接受只记录人工决定：不合并、不部署、不推送、不覆盖原项目。你仍自行处理 patch。

交付内容通常包含 manifest、完整 patch 与检查证据；界面中的 patch 预览有显示上限，下载是完整文件。

## 2. 回答执行器的问题

- 待我决定会按等待时间/阻塞/权限等排序；打开后阅读上下文再回答。
- 答案先记录为“本地已记录（尚未写到原生）”，只有执行器确认后才变为已应用；界面不会自行升级。
- 问题过期、来源变化时会拒绝；重新读取后再答，不要重复提交同一答案。

## 3. 拒绝/停止

- 停止/暂停只对当前工作可用；按钮来自服务端 actions，客户端不自造。
- 停止可能出现“停止中/不确定”；此时保留现场，不要删除目录或重复点停止。
- 拒绝候选与停止工作不会删除历史；它们只是明确的决定。

## 4. 交接给下一位试用者

交接的是**范围与证据**，不是账号或数据：

- 仓库与分支：`codex/g4-trial-experience`（F 自有路径）。
- 状态记录：`reports/trial-experience/wave25-status.json`（source、endpoints、视口、命令、未测范围）。
- 集成说明：`reports/trial-experience/main-integration.zh-CN.md`（main 接线与 props 语义）。
- 证据：`apps/console/e2e/trial/report-states.json`、`report-http.json` 与 `screenshots/`。
- 用户文档：本目录。

不要交接：`bootstrap.key`、`api.key`、模型 key、`model.json`、`.assistant-settings.json`、SQLite、原生 profile、`.local-state` 副本。

## 5. 试用前的最小检查（交接双方一起做）

```sh
pnpm install --frozen-lockfile
pnpm doctor                 # 启动前诊断
pnpm start                  # 记录终端打印的地址
```

然后：

1. 打开主对话，发一条仅讨论的消息（若已配置模型）。
2. 打开“执行器连接”，记录真实状态与原因。
3. 导入一个测试项目，确认项目筛选与新建委托草稿。
4. 若执行器可用，完成一个最小委托并审阅；若不可用，明确记录“未达”，不要改用固定流程冒充原生。
5. main 接线后，再打开“试用准备”核对状态条与四类动作。

## 6. 证据的边界

- 受控固定流程、浏览器 UI、真实 HTTP readiness 的通过，**都不能**单独证明：
  原生执行器已连接、真实模型质量、完整产品发布、费用/预算收益、恢复授权。
- 任何“全产品 PASS”的结论只由独立验收（E）给出；本目录与 F 的报告不替代它。
- 运行字节改变后需要重新冻结并由 E 重新验收；仅文档变化不重新冻结。
