# 首次启动与配置

## 1. 启动

```sh
pnpm install --frozen-lockfile
pnpm start
```

终端会打印网页地址（默认 `http://127.0.0.1:5180`，本地 API `8796`）。打开后先看到主对话工作台。

- 如果页面提示会话失效：按页面提示重新建立本地会话；凭据来自你本次启动的私有状态目录。
- 如果启动失败：`pnpm doctor` 会列出实际原因；不要删除状态目录来“修好”它。
- 想试用独立环境：`pnpm start --state .local-state/my-trial --port 5192 --api-port 8808`。端口不要和已有实例重复。

## 2. 两件不同的事：对话模型和开发执行器

| | 对话模型 | 开发执行器（Codex 等） |
| --- | --- | --- |
| 用在哪里 | 主对话、提案/决定讨论 | 明确委托后的编码、检查、交付 |
| 在哪里配置 | 顶栏“模型设置”/偏好设置 | 由本机准入与“执行器连接”视图决定 |
| 未配置时 | 对话不能开始 | 开发委托不可用，但普通对话仍可用 |
| 是否会因对话配置而自动可用 | — | 不会。执行资格独立判定 |

打开“模型设置”后，启用模型配置本身不会发送模型请求。页面上显示的模型离线/连接中断只影响对话通道，不会把你的工作或队列清空。

## 3. 判断“是否就绪”的正确方式

- **配置已具备**：配置事实成立（例如存在已准入原生 profile 与项目），但不是“连接已验证”“任务必成功”“已授权执行”。
- **固定流程**：受控测试通路，不会运行原生执行器。
- **只读恢复**：可以审阅历史与来源，不能派工、批准或恢复授权。
- **未知**：没有观察到状态，不等于正常。
- **不能派工/暂不可用**：按显示的原因处理（未安装、版本不匹配、需要认证等）。

“试用准备”视图把这些事实集中到一页（左侧导航“试用准备”）；各状态的准确含义见 [试用准备视图](03-trial-readiness.zh-CN.md)。

## 4. 试用准备入口

登录后打开左侧（手机底部）**试用准备**：它集中显示对话模型、开发执行、当前项目/会话，并把四类既有入口（模型设置、项目导入、执行器检查、主对话）放在一起。各状态与文字含义见 [试用准备视图](03-trial-readiness.zh-CN.md)。

“配置已具备”只说明配置事实；是否真的能派工仍看执行器状态与你在委托确认页的选择。

## 5. 首次配置建议顺序

1. 启动并确认页面能打开（会话正常）。
2. 打开“模型设置”，配置对话模型；先发一条普通对话确认可用。
3. 打开“执行器连接”，确认本机执行器的实际状态；若未准入，先继续用对话/审阅，不要改用固定流程冒充原生。
4. 导入一个项目（见 [项目与主对话](02-projects-and-conversation.zh-CN.md)）。
5. 需要开发时，在对话中明确委托；确认页出现的执行器、允许路径和验收标准要逐项核对。

## 6. 不要做的事

- 不要用固定流程截图当作 Codex 已接入。
- 不要因为“配置已具备”就认为可以无人值守执行。
- 不要把 `model.json`、`.assistant-settings.json`、`*.key`、数据库或原生 profile 提交到仓库或发到聊天里。
- 不要为绕过只读恢复去复制旧数据库或删除 restore marker。
