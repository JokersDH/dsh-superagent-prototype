# 项目与主对话

## 1. 导入项目

主对话仍是最常用的入口；项目是它的上下文。

1. 在左侧“项目与工作”标题右侧点击 **导入项目**（文件夹加号图标）。
2. 填写 **Git 仓库根目录**（本机绝对路径）。项目名称可留空，默认使用目录信息。
3. 选择注册检查（默认 `node_test`）。环境策略保持默认 `none`；只有你明确准备了离线缓存时才选择 `existing_only`/`offline_install`，并填写缓存目录。
4. 提交后，新项目会出现在项目筛选里，并自动进入新建委托草稿；取消草稿不会删除项目。

导入不会执行代码，也不会自动派工。路径必须是你有权访问的本地 Git 仓库；不要指向他人的 home 目录或系统目录。

## 2. 识别“当前项目”和“当前对话”

- 顶栏中间显示当前工作区与项目；左侧项目筛选有选中态。
- 左侧“当前对话的工作”只列出当前对话的工作，不是全局历史。
- 切换项目会改变筛选与新建委托的默认项目，不改变已有对话内容。
- 会话目录可以切换历史对话；未发送的草稿按会话保留，切回来还在。
- 手机端“工作空间”和“工作详情”是互斥抽屉，关闭按钮、遮罩和 Escape 都能退出。

“试用准备”视图（main 接入后）会额外显示当前项目与当前对话名称，但项目行是**只读事实**，不是选择器；选择仍走左侧既有导航。

## 3. 主对话

- 普通消息用于讨论，不会授权编码。
- `Ctrl/⌘ + Enter` 发送；发送后等待流式回复。刷新页面会恢复本实例已保存的部分回复。
- 想基于当前工作讨论时，明确选择“使用当前工作上下文”；否则消息属于当前项目会话。
- 模型离线时：可以继续阅读、回答已有问题、停止/暂停既有工作；新回复不可用。页面不会自动改用固定流程或其它模型。

## 4. 明确委托（开发）

1. 在对话输入区点击委托/新建委托，或从“新建委托”打开草稿。
2. 核对项目、目标、允许路径、验收标准和执行器。执行器必须显示为可派工；固定流程会标明“固定流程”。
3. 确认后产生 Work/Ticket，执行发生在独立 worktree；你的原项目不会被直接改写。
4. 执行中出现的问题会进入“待我决定”；回答后继续。
5. 完成后到“工作与交付”审阅验证与 patch，详见 [交付审阅与交接](05-review-and-handoff.zh-CN.md)。

## 5. 一个受控的首次 journey（约 10 分钟）

1. 导入一个测试用 Git 仓库（可以是空仓库）。
2. 发一条普通对话：“用三句话说明这个项目可以怎么开始”，确认模型通道可用（如果未配置模型，先按 [首次启动](01-start-and-configure.zh-CN.md) 配置）。
3. 打开“执行器连接”，记录当前执行器状态；若不可派工，继续只读/对话，不要改用固定流程冒充原生。
4. 如果执行器可用，新建一个很小的委托（例如“在 README 末尾加一行说明”），核对范围与验收标准后确认。
5. 在工作详情中查看阶段、问题、验证与交付；完成后接受或拒绝。
6. 打开“试用准备”（main 接入后）核对：当前模式、对话模型、开发执行是否与刚才一致。

## 6. 长项目名、多个项目、空项目

- 项目很多时用左侧筛选，不要靠搜索框代替项目选择（工作搜索只作用于当前对话）。
- 项目名很长时会在自己的区域内换行或截断；顶栏和操作按钮尺寸保持稳定。
- 没有项目时，主对话仍可使用；开发相关操作会要求先导入项目。
