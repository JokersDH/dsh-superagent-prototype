# 个人 Agent 助理 · 产品使用手册

适用于M系列Mac、macOS14及以上的安装版。把需求讨论、开发执行、问题确认和代码交付放在一个本机工作台。

## 1. 它能帮你做什么

你可以先讨论需求，再把明确的开发目标委托给Codex。助手在独立工作区修改代码，运行你选择的检查，把变更补丁和检查结果交给你审阅。项目、对话、问题和交付记录保存在本机，正常关闭重开后仍可查看。

| 功能 | 你可以怎样使用 |
| --- | --- |
| 需求讨论 | 分析报错、梳理方案、拆解开发目标；普通发送用于讨论 |
| 开发委托 | 修复缺陷、增加小功能、补测试；确认委托后才开始执行 |
| 多项目与会话 | 导入自己的Git项目，按项目查看工作和历史对话 |
| 集中问题 | 在“待我决定”处理执行器实际提出的权限或业务问题 |
| 运行中补充 | 选中Work，切到“当前工作”，给同一正在执行的工作补充要求 |
| 停止工作 | 在工作详情点击“停止工作”，等待后端确认停止和资源归还 |
| 检查与交付 | 查看注册检查、完整patch和产物，明确接受当前候选 |
| 历史与来源 | 查看历史工作、上下文来源、已记录的明确决定；不会自动把临时做法学成永久规则 |

当前主要支持本机Codex执行。是否能主动提出结构化澄清问题取决于执行器的实际模式；权限问题逐项确认。自动合并、push、部署和无人工审阅的接受不在当前默认流程中。

## 2. 安装与打开

1. 打开提供的DMG。
2. 把“Personal Agent.app”拖到“Applications / 应用程序”。
3. 从“应用程序”双击打开“个人 Agent 助理”。
4. 等窗口显示“工作台已就绪”；浏览器会打开本机工作台，也可点击“打开工作台”。
5. 首次进入后配置对话模型，并导入自己的Git项目。

应用附带运行所需的Node。普通安装不需要你克隆源码或运行pnpm构建。

开发执行需要本机Git、已登录的Codex CLI，当前验证版本为0.164.0。没有就绪的执行器时仍可打开工作台、配置模型、讨论和查看已有记录，开发委托会明确禁用。不要把对话模型的Key与Codex登录混为一项。

这是内部个人试用包，目前没有Apple Developer ID公证。若系统提示“无法验证开发者”，可按你所在组织允许的macOS方式，从系统设置的隐私与安全页面确认打开；不要关闭系统安全策略。其他平台和更高Codex版本需独立验证。

## 3. 第一次配置：两条连接分别设置

### 对话模型

在工作台点击“偏好设置”，填写：

- 模型端点：你的OpenAI兼容服务地址，例如https://your-gateway.example/v1。
- 模型名称：服务商实际提供的模型ID。
- API Key：只填入本机设置，不要写进需求消息、代码仓或分享包。
- 如果端点是HTTP，按页面要求明确允许未加密传输；优先使用HTTPS。

“保存配置”只表示已保存到本机，不表示已联网验证。随后你自己发送一条普通消息，收到回复才有这条连接实际可用的证据。

### Codex开发执行器

Codex使用自己的本机安装和登录。你可以在终端核对版本与登录状态：

~~~sh
codex --version
codex login status
~~~

需要登录时，使用自己的账号运行codex login，然后重新打开本应用。应用不会替你借用另一个人的认证，也不安装或升级全局Codex。

## 4. 导入自己的项目

点击工作台侧栏的“导入项目”，选择：

1. 有至少一次提交的Git仓库根目录。
2. 干净、已提交的当前基线。
3. 项目实际使用的检查，例如Node测试、npm test或pnpm test。
4. 页面提供的依赖环境选项。首次建议选择已有可运行检查、无需新增依赖的小Node项目。

项目有未提交改动时，先自行提交或妥善处理，应用不会替你reset、clean或覆盖工作。复杂monorepo及任意依赖安装不能由一个成功小项目推断为全部支持。

导入不会自动开始编码。你仍需明确创建开发委托。

## 5. 完成第一项开发任务

### 先讨论，再明确委托

“主对话”用于讨论；直接输入一句“帮我修改”并普通发送，不等于已经开始修改文件。写好目标后，点击“委托执行”，核对项目、执行器、允许范围和检查标准，再创建。

建议首次目标：

> 修复一个已经有测试覆盖的边界问题；保持公共接口，不新增依赖，补充必要测试，并通过项目现有检查。

也可以选择一个范围清楚的小功能。避免一开始就委托整个系统重构。

### 查看执行并回答问题

在“工作与交付”或侧栏选中该Work。执行器提出的问题会进入“待我决定”。权限批准只适用于当前请求，不等于以后自动允许所有操作。

“本地已记录”“已写入原生”“原生已应用”是不同阶段。结果未知时先查看原请求和回执，不新建另一项任务来重复同一业务操作。

### 运行中补充要求

选中正在运行的Work，点击输入框下的“当前工作”，再发送补充。例如：

> 补充：保留原错误码，新增测试覆盖空输入，不改变现有调用方式。

“主对话”和“当前工作”的消息分别显示；重开后查看工作补充历史，也需要切到对应的“当前工作”。任务已经结束时，“继续工作”会进入后续执行，不能当作同一次运行中的补充。

### 检查、审阅、接受

1. 等待机器检查。
2. 查看检查输出、完整变更补丁和产物。
3. 确认目标满足后，接受当前候选。
4. 下载patch，在自己的项目中审阅、应用并提交。

接受不自动合并或push到原仓库。机器检查失败不能靠人工接受绕过；应继续定位问题或按原工作流程修订要求。

## 6. 关闭、停止与再次打开

关闭网页或桌面窗口，不会停止后台任务。桌面应用保留在Dock，重新点击可打开工作台。

- 停止某项任务：工作详情里的“停止工作”。
- 停止整个本地服务：桌面窗口里的“停止服务”。
- 退出桌面应用：菜单“退出个人 Agent 助理”，会尝试正常停止自己的服务。
- 重新启动：再次打开应用，或在停止后的窗口点击“打开工作台”。

有工作运行时，先检查其进度、等待交付或明确停止，再退出服务。停止尚未确认时，应用会保留现场并提示查看日志，不把按钮点击成功当作物理停止。

## 7. 数据、分享与版本

桌面安装版的配置、对话和工作记录位于自己的：

~/Library/Application Support/PersonalAgent/Desktop/

日志位于其logs子目录，桌面窗口和应用菜单都可“打开日志”。模型配置只放私有config目录，分享DMG不携带你的Key、原生账号或工作数据。

旧Preview版本的私有根保留在原位置。新桌面版默认使用独立Desktop根，不自动迁移旧记录、旧授权或旧执行队列。需要历史迁移时，先使用已有备份/只读恢复流程核对来源，再另行明确授权。

分享给同事时，只分享提供的DMG和本手册。同事使用自己的模型连接与Codex账号，不复制你的Application Support目录。

## 8. 常见问题

### 启动出现UNVERIFIED或process_start不一致

早期包把系统返回的英文/中文启动时间直接比较，会误判同一进程。新版已固定出生时间的语言观测，并严格兼容已记录的中英文格式；真正不同的启动时间、PID、UID、命令和目录仍会拒绝。

请使用新的DMG安装版，避免继续运行旧ZIP中的Start.command。新桌面版采用单独的稳定数据根，不会自动结束旧预览实例。若仍失败，使用“打开日志”提供错误摘要，不要手删数据库或按PID强杀。

### 新解压文件夹后多了“2”，打不开

不要在每个临时解压目录分别启动。把.app安装到“应用程序”，从那里打开；已经核实的同版本运行实例会复用。运行中不要移动.app文件夹。

### 能聊天但不能开发

检查Codex是否存在、版本是否已验证、是否使用自己的账号登录，以及是否已经导入可执行项目。填对话模型Key不会自动让Codex就绪。

### 看不到工作消息或补充

先选中Work，再切到“当前工作”。普通主对话只显示讨论上下文，不把所有工作消息混在一起。

### 检查失败、环境未就绪或状态未知

打开该Work的检查/环境详情，按具体原因处理。保留原工作、候选和回执；不要清库、清凭据或跳过身份与检查守卫。

## 9. 当前适用范围

先用于M系列Mac、Codex0.164.0和已支持检查的本地项目。主路径已验证真实开发、审批答复、运行中补充、停止、产物接受和正常重开；本次安装修复只做零模型启动验收，没有新增真实模型额度。

其他Mac、长时间运行、大型工程依赖、其他CLI版本和其他执行器需分别验收。完整方案B继续保留，CAC、自动接受和研究收益不构成本次安装的承诺。
