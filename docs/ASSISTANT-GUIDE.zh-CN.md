# 个人开发助手 MVP：使用指南

当前已接通本机 Codex：从网页确认开发委托，执行器在独立 Git worktree 实现代码，运行注册的检查，再由你审阅当前 patch 并接受交付。主对话用于讨论需求；真正执行以明确确认的委托为准。

当前原生范围为本机 macOS arm64、Codex 0.164.0，先支持普通 Node 项目的闭环。它不是三个执行器全部可用或完整 G2 稳定版本的声明。

## 第一次使用

1. 双击仓库根的 `start.command`，或在仓库运行 `pnpm start`。
2. 打开 `http://127.0.0.1:5180/`，本机入口无需手动粘贴令牌。
3. 可以使用默认的“我的开发项目”，或从工作空间旁的“导入项目”选择已有提交的本地 Git 仓库根目录，并选择检查方式。
4. 在主对话输入开发需求，点击输入框旁的“委托执行”图标。确认项目、Codex 执行器、允许路径与检查标准，再点击“创建委托”。
5. 工作会排队并执行。如果执行器提出支持的原生问题，工作详情的“待决定”里回答；回答记录、写到原生、原生确认分别显示。
6. 机器检查通过后，查看“完整变更补丁”和“检查证据”，确认目标达成，再点击“接受当前候选”。

例如可以对默认 Node 项目委托：

> 增加 src/slugify.mjs，导出 slugify(text)：英文字母转小写，保留数字，连续其他字符变为一个连字符，去掉首尾连字符。补充边界测试并运行 node --test，不引入外部依赖。

只点击普通“发送消息”会进行模型讨论。使用“委托执行”时，输入文本先进入确认表单，确认前不会开始编码。

## 项目与代码在哪里

默认项目位于 `~/.local/share/superagent-personal/projects/starter`，是一个普通 Git/Node 项目。也可导入自己的仓库。首次导入和新建委托要求原项目已有提交且工作树干净；已有未提交修改会明确拒绝，保留你的文件。

每项工作的“代码位置”显示：

- **原项目**：你选择的仓库。
- **工作区**：Codex 本次实际修改的独立 worktree，可以复制路径在 IDE 中打开。
- **基线**：创建工作区时的 Git 提交。

接受交付会确认本次候选及验证结果，不自动覆盖原项目、合并、提交或推送。产物提供完整 `changes.patch` 和检查证据。审阅后在原项目应用 patch，并提交为下一轮工作的基线。

原生工作通常有三个产物：交付清单、完整变更补丁、检查证据。固定流程测试额外包含一个固定输出文件，两者会分别命名。

## 检查与工作控制

导入时可选择 `node --test`、`pnpm test` 或 `npm test`，它们注册为服务端检查；模型不能把回复中的任意命令变成验收命令。机器检查失败不能被人工接受绕过。

当前先完成不依赖外部安装的 Node 闭环。有依赖的项目需要其隔离工作区具备可用依赖；当前不自动联网安装、升级包管理器或运行安装脚本。依赖准备不足会导致检查不能通过，环境准备模块由独立任务继续扩展。

“暂停派工”用于尚未开始的工作；“停止”要求确认实际 owned 资源停止。仅收到 native ACK 或进程退出不足以释放屏障，未知状态会继续阻止新写入。修订、继续和重试仅在当前版本允许时提供。

刷新或关闭网页不会重新 begin。服务重开后保留已交付记录、产物和命令回执；运行中服务故障会先保守核对物理资源，不自动重复原生 begin/deliver/answer。完整中途故障恢复与真实审批/澄清分支仍按独立原生验收范围推进。

## 对话模型与开发执行器

顶部“对话模型”控制需求讨论，支持本机配置的 GLM-5.3、GLM-5.3-Flash、DeepSeek-V4.1-Flash-1017。流式回复在生成时逐段显示，完成后持久保存，网页刷新不会重新计费请求。

**开发执行器**使用本机 Codex 的既有认证与原生工具循环，和主对话网关分开。这个 MVP 不修改你的全局 Codex 账号配置。ZCode、DeepSeek Harness 和 CAC 尚未接入本轮生产执行路径。

主对话 key 存在仓库外 `~/.config/superagent-personal/model.json`，文件 600、目录 700；前端不接收实际 key。当前对话网关为 HTTP，传输不加密。对话只取有限文本上下文，不自动上传仓库；开发委托的原生执行器会读取你明确选择的项目工作区。

任务模板、回复复制和 Markdown 导出仍可用于计划与交接。工作锚定记录与普通对话上下文隔离；开发回归使用独立会话。

## 启停与开发检查

```sh
pnpm start      # 启动本机原生 MVP；已有实例则复用
pnpm stop       # 停止服务，保留配置、工作及产物
pnpm restart    # 后端改动后重启
```

`stop.command` 可用于停止。需要只验证固定流程时，可用另一个端口/私有 state：

```sh
pnpm dev:workbench --fixture --port 5181 --api-port 8797 --state /tmp/pa-fixture-workbench
```

固定 profile 只执行 scratch 流程。真实 MVP 的检查与证据见 `reports/releases/native-mvp/`；`pnpm check:native-product`、`pnpm check:native-browser` 会执行真实模型任务，属于显式原生验收，日常自动回归使用本地 fixture。
