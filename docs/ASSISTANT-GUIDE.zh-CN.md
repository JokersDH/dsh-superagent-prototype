# 个人开发助手 MVP：使用指南

当前已接通本机 Codex：从网页确认开发委托，执行器在独立 Git worktree 实现代码，运行注册的检查，再由你审阅当前 patch 并接受交付。主对话用于讨论需求；真正执行以明确确认的委托为准。

当前原生范围为本机 macOS arm64、Codex 0.164.0，支持无依赖 Node 项目及使用授权离线缓存的普通单包 pnpm 项目。它不是三个执行器全部可用或完整 G2 稳定版本的声明。

缺少Codex、版本不符或检测失败时，当前源码仍可启动个人对话、上下文预览、使用记录及原始来源审阅。页面显示具体原因，开发委托与旧任务控制禁用，不会自动改用固定流程。普通对话仍需要已配置的对话模型；仅启动不会发送模型请求。

最新建议工作台：[http://127.0.0.1:5191/](http://127.0.0.1:5191/)，API8807，独立数据目录`.local-state/wave15-candidates-preview`。已识别本机准入Codex及对话配置。它不会复制旧实例的会话或工作；原5180–5190入口和数据继续保留。下文5189/5190是各自历史版本入口。

仅对话新版预览：[http://127.0.0.1:5190/](http://127.0.0.1:5190/)，API8806，独立空数据目录。顶部“开发执行已关闭”是主动选择的状态；需要开发执行时继续使用下方5189原生预览。两个入口不自动复制对话或任务。

最新上下文历史与来源正文预览：[http://127.0.0.1:5189/](http://127.0.0.1:5189/)。它使用新的独立数据目录，原5180–5188实例和历史保留，没有迁移旧对话。新根的使用记录从后续实际发送所选上下文开始产生。`pnpm start`可能复用旧实例；体验本次功能请打开上述新版入口。

## 新版工作台

新版使用主对话、工作与交付、待我决定、执行器连接四个视图。左侧保留项目筛选和当前对话的工作；选择工作后，阶段条显示工作名称、执行阶段和待决定数量，右侧查看目标、问题、检查和产物。切换视图保留尚未发送的对话草稿。

工作目录的搜索/状态筛选作用于当前对话，尚不代表服务端全部历史会话已可搜索。原生执行器与固定流程测试分别呈现；目录中的“已准入”也不表示所有原生操作和平台都已认证。手机端使用底部导航和互斥的项目/详情抽屉。

会话目录、项目设置版本化、跨项目待办、明确提案/决定、上下文预览与单条消息附加、使用记录及原始正文、交付记录已接通。恢复激活与当前源码安装发行仍按[第十三轮任务](../agent-tasks/product-wave-13/README.zh-CN.md)分别验收；恢复材料或完整空库不代表可以启动旧工作。

## 从回复建议创建工作或记录决定

1. 打开“模型设置”，显式启用“提案建议”。默认关闭，启用设置本身不会请求模型。
2. 在项目对话里讨论需求，例如“整理一项保留原错误码的项目决定”。回复完成后，展开该回复下的“提案建议”。是否有建议取决于这一次模型返回；没有建议也可以继续普通讨论或手动创建提案。
3. 点击对应“预览提案”。原回复的建议内容只读；创建工作需核对执行器、允许路径和验收标准，修订工作还需填写新的工作目标。预览不创建工作。
4. 在确认页核对来源、范围、期限及验收标准，点击“确认创建”“确认修订”或“确认记录”；也可以拒绝。工作创建后沿用现有执行、验证及人工接受流程。

模型建议不会自动派工、授权外部动作或代替你的确认。网络丢响应时点击“核对原请求”，刷新后也可从顶栏“创建提案”恢复核对；不要另建一个重复命令。来源、目标工作或原结果变化时，返回重新读取建议。

普通文字仍逐段流式显示；若服务只返回结构化正文，会在完整验证后显示一次。当前配置网关的tools支持尚未实测。若启用后提示连接无法使用提案建议，关闭该设置后再自行发送；系统不会自动补发、切模型或修格式重试。关闭设置不删除历史建议，也不使原建议自动生效。

该偏好保存在仓库外模型配置旁的`.assistant-settings.json`文件，权限600；原`model.json`保持旧实例可读。共享同一私有配置的新版实例会在下一次读取时看到该偏好，旧版仍保持其原行为。

## 使用所选上下文对话

1. 在一个项目的对话里发送或打开已有消息。可先在主输入框写好下一条草稿，不必普通发送。
2. 点击顶栏“上下文预览”，选择项目、当前会话内工作及来源：工作合同/验证、有效项目决定、项目信息、会话消息或交付元数据。
3. 在“本条消息”确认要问的内容，点击“预览消息”，核对来源、遗漏、预算与期限，再点击“确认发送”。仅“生成预览”不会调用模型。
4. 回复沿用原流式对话。消息旁“上下文来源”读取该条消息实际保存的来源绑定，可以查看摘要及截断记录；这份审计说明所选输入，不是模型正确性的证明。

工作在此处只是参考上下文，不会变成补充执行、创建委托或派单。默认不自动附加资料，也不扫描仓库文件正文；交付来源只包含已发布元数据。所选项目决定可以来自项目内其他会话，但会话消息仅限所选原会话及工作。

发送前来源、合同、授权或期限变化会明确拒绝，保留草稿，需重新预览。网络丢响应时使用“核对原请求”，不要另发一条相同请求；刷新后仍保留原命令，过期或模型连接暂不可用也能核对已完成的原回执。模型结果未知不会自动再次请求。原主输入框只在发送内容和原草稿全文一致时清空。

单条上下文消息最多16384字符，资料预算另行设置。没有配置模型连接的实例保留只读预览，不提供新的上下文消息发送。

## 查看使用记录和原始来源

打开“上下文预览”，切换“使用记录”。可按项目、当前会话及工作筛选，继续翻页；取消“仅当前会话”后可审阅该项目其他会话的记录。选择一条记录查看当时保存的原始来源，详情右上角可返回原会话。手机使用详情左上角的返回入口回到列表。

常见消息、决定和目标会展示可读正文，摘要及原始记录可另行展开，复制按钮复制的是原始内容。后来来源发生变化不会替换这份记录，原来发生的截断仍会保留。预览过期或模型连接不可用不妨碍历史审阅，也不会因此重新请求模型或授权执行。原文件缺失、内容无法核对或授权范围缩小时会显示对应状态，不把当前重新检索的内容冒充原文。

使用记录表示当时确认的上下文选择，不单独证明模型一定收到或正确使用了这些内容；发送异常仍以该条消息的回执和提示为准。

工作台每页读取20条，同一筛选最多展示200条；跨会话工作菜单有独立的最近200项上限。服务重开后，如果已有完整回复结果但消息发布失败，会核对后补回原结果；只有请求记录而无完成结果时保持未知，不自动重发。

## 第一次使用

1. 双击仓库根的 `start.command`，或在仓库运行 `pnpm start`。
2. 打开 `http://127.0.0.1:5180/`，本机入口无需手动粘贴令牌。
3. 可以使用默认的“我的开发项目”，或从工作空间旁的“导入项目”选择已有提交的本地 Git 仓库根目录，并选择检查方式。
4. 在主对话输入开发需求，点击输入框旁的“委托执行”图标。确认项目、Codex 执行器、允许路径与检查标准，再点击“创建委托”。
5. 工作会排队并执行。如果执行器提出支持的原生问题，工作详情的“待决定”里回答；回答记录、写到原生、原生确认分别显示。
6. 机器检查通过后，查看“完整变更补丁”和“检查证据”，确认目标达成，再点击“接受当前候选”。

例如可以对默认 Node 项目委托：

> 增加 src/slugify.mjs，导出 slugify(text)：英文字母转小写，保留数字，连续其他字符变为一个连字符，去掉首尾连字符。补充边界测试并运行 node --test，不引入外部依赖。

只点击普通“发送消息”会进行模型讨论。使用“委托执行”时，输入文本先进入确认表单，确认前不会开始编码。

## 项目与代码在哪里

默认项目位于 `~/.local/share/superagent-personal/projects/starter`，是一个普通 Git/Node 项目。也可导入自己的仓库。首次导入和新建委托要求原项目已有提交且工作树干净；已有未提交修改会明确拒绝，保留你的文件。

每项工作的“代码位置”显示：

- **原项目**：你选择的仓库。
- **工作区**：Codex 本次实际修改的独立 worktree，可以复制路径在 IDE 中打开。
- **基线**：创建工作区时的 Git 提交。

接受交付会确认本次候选及验证结果，不自动覆盖原项目、合并、提交或推送。产物提供完整 `changes.patch` 和检查证据。审阅后在原项目应用 patch，并提交为下一轮工作的基线。

原生工作通常有三个产物：交付清单、完整变更补丁、检查证据。固定流程测试额外包含一个固定输出文件，两者会分别命名。

## 检查与工作控制

导入时可选择 `node --test`、`pnpm test` 或 `npm test`，它们注册为服务端检查；模型不能把回复中的任意命令变成验收命令。机器检查失败不能被人工接受绕过。

普通单包 pnpm 项目可以在导入时选择“从授权缓存离线准备”，填写项目之外已预热的 pnpm store 根目录，并选择 `pnpm test`。该目录应是预热时 `--store-dir` 指定的根目录，不能指向原项目的 node_modules。准备由独立 Runner 执行，先核对 Node/包管理器、锁文件和依赖，再开始 Codex 工作；不联网、不升级包管理器、不执行安装生命周期脚本或项目安装钩子。项目中不支持的安装配置会明确阻断。

“仅验证已有依赖”检查的是本次隔离工作区，不能借用或链接原项目的 node_modules；新工作区缺依赖时会受阻。“不准备依赖”保留原有 Node 流程。工作详情显示依赖环境的等待、准备、复验或阻断状态。依赖、package.json、lockfile 或归属变化后，旧环境凭证不能用于验证和接受。环境目录不会进入业务 patch。npm 离线安装和任意 monorepo 尚未准入。

“暂停派工”用于尚未开始的工作；“停止”要求确认实际 owned 资源停止。仅收到 native ACK 或进程退出不足以释放屏障，未知状态会继续阻止新写入。修订、继续和重试仅在当前版本允许时提供。

刷新或关闭网页不会重新 begin。服务重开后保留已交付记录、产物和命令回执；运行中服务故障会先保守核对物理资源，不自动重复原生 begin/deliver/answer。完整中途故障恢复与真实审批/澄清分支仍按独立原生验收范围推进。

## 对话模型与开发执行器

顶部“对话模型”控制需求讨论，支持本机配置的 GLM-5.3、GLM-5.3-Flash、DeepSeek-V4.1-Flash-1017。流式回复在生成时逐段显示，完成后持久保存，网页刷新不会重新计费请求。

**开发执行器**使用本机 Codex 的既有认证与原生工具循环，和主对话网关分开。这个 MVP 不修改你的全局 Codex 账号配置。ZCode、DeepSeek Harness 和 CAC 尚未接入本轮生产执行路径。

主对话 key 存在仓库外 `~/.config/superagent-personal/model.json`，文件 600、目录 700；前端不接收实际 key。当前对话网关为 HTTP，传输不加密。对话只取有限文本上下文，不自动上传仓库；开发委托的原生执行器会读取你明确选择的项目工作区。

任务模板、回复复制和 Markdown 导出仍可用于计划与交接。工作锚定记录与普通对话上下文隔离；开发回归使用独立会话。

## 启停与开发检查

```sh
pnpm start      # 启动本机原生 MVP；已有实例则复用
pnpm stop       # 停止服务，保留配置、工作及产物
pnpm restart    # 后端改动后重启
pnpm doctor     # 只读核对服务、项目、执行器和恢复阻断
```

只使用对话时，使用已有仅对话预览，或选择自己的空闲端口和独立数据目录：

```sh
pnpm start --discussion-only --port 5190 --api-port 8806 --state .local-state/wave13-readiness-preview
```

该命令可以复用经身份核对的同模式实例，不能把仍启用执行的实例当成仅对话实例。移除启动参数不会在线启用执行器；后续启用需要在明确的重启流程中重新核对本机profile及原有资源。旧的工作、回执、原生绑定和队列保持原样，“未就绪”不表示旧原生进程已经停止。存在恢复标记时仍以恢复只读为准，对话模型也不会启动。

2026-11-10 的带依赖预览实例使用 `http://127.0.0.1:5181/` 与独立状态目录，原 5180 实例继续保留。可使用以下入口复用、诊断或停止新版实例：

```sh
pnpm start --port 5181 --api-port 8797 --state .local-state/environment-preview
pnpm doctor --state .local-state/environment-preview
pnpm stop --state .local-state/environment-preview
```

本次上下文消息实例使用以下独立入口，不需要停止或升级旧实例：

```sh
pnpm start --port 5188 --api-port 8804 --state .local-state/wave10-context-use-preview
pnpm doctor --state .local-state/wave10-context-use-preview
```

`stop.command` 可用于停止。需要只验证固定流程时，可用另一个端口/私有 state：

```sh
pnpm dev:workbench --fixture --port 5181 --api-port 8797 --state /tmp/pa-fixture-workbench
```

遇到无法打开、启动记录不符或工作停在恢复核对时，先运行 `pnpm doctor`。它核对真实进程、监听端口和已认证的只读接口，不安装依赖、不调用模型，也不自动修复或结束进程。固定流程、原生执行和未接入的环境准备会分别标注；诊断通过只代表本次观察到的范围。

需要保存可分享的诊断摘要时，使用 `pnpm doctor --json --output /tmp/pa-diagnosis.json`；输出文件必须尚不存在，权限为 600，不包含 key、会话原文或数据库。诊断其它私有实例时增加 `--state /tmp/pa-fixture-workbench`。任一阻断会使诊断命令以非零退出。

固定 profile 只执行 scratch 流程。真实 MVP 的检查与证据见 `reports/releases/native-mvp/` 和 `reports/releases/environment-mvp/`；`pnpm check:native-product`、`pnpm check:native-browser`、`pnpm check:environment-native` 会执行真实模型任务，属于显式原生验收，日常自动回归使用本地 fixture。
