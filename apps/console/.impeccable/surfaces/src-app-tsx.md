# Main Workbench

Mode: Operate. Scope: the existing React console shell, navigation, conversation, decision inbox, task/agent directories and contextual delivery inspector. User: a developer doing sustained project work, later internal colleagues on their own machines. Preserve authorization and all current HTTP/schema workflows.

## Direction contract

THESIS: A precise conversation workspace. The main dialogue leads; projects, live tasks, decisions and verified delivery are visible context, with detail opened when needed. This is a working screen, never a landing page or a collection of decorative cards.

OWN-WORLD: White reading canvas, a compact graphite navigation rail, cool neutral project navigation, evergreen interaction accents, amber decisions and restrained semantic colors. Fixed text sizes, crisp fine rules and disciplined spacing. Familiar web buttons, inputs, tabs and lists carry every operation.

STORY: The user sees the current project and conversation, notices an actual decision or active task, then moves between discussion, explicit delegation, questions and verified changes. Counters and statuses must come from configuration/snapshot data. Unavailable capabilities do not become product claims.

FIRST VIEWPORT: A 52px utility header; 56px graphite rail and a 232px project/task navigator on desktop; a generous white conversation column with a bounded reading measure and substantial composer; a 350px contextual inspector when requested. At 390px, navigation and detail are mutually exclusive drawers with reachable close controls. The primary send/delegate commands remain next to the draft. The signature is a compact live work-stage strip connected to the selected task, with precise phase and pending-decision signals.

FORM: The sixth grounded source is a technical conference program's typographic rhythm and clear agenda signals, translated only into type, palette, density and the live-stage strip. Seed d7807279. User chose the precise graphite/white/evergreen direction and conversation-led workflow. Catalog challengers were declined for losing developer identification and clarity; kept discipline: Metro's hierarchy, catalog scanability, transit's status distinction, tabs' contextual layering, timetable's stable cells, exposure record's contrast. No literal costumes, giant type, hatch decoration or off-axis panels.

FINISH: unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, DESIGN.md, and every shipping raster carrying its provenance

## Implementation Constraints

Code-led because this session has no callable image-generation tool. Reuse lucide for the actual app iconography. UI text names actual actions/states, not architecture or styling. No model call is needed for design verification. Keep main selectors/classes used by product E2E where possible. Record open backend gaps in the roadmap rather than inventing synthetic production data.
