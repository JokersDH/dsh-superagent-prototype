## 实施步骤

1. 从固定上游 commit 提取 core 与原测试到隔离试验，保留 MIT、版权和 provenance；验证 runtime/type graph 均不含 DSH 宿主。
2. 运行独立 144-test baseline，锁最小测试依赖并保存命令、import graph、版本与结果；失败时记录具体依赖阻塞，先裁剪。
3. 把公共类型草案转成单一运行时 schema 来源和生成流程，补非法/旧版本消费者 fixture；冻结接口、身份、错误和版本规则。
4. 验证拟议 Node/pnpm/better-sqlite3 发行组合，输出 native-load、SQLite engine 检查和 root bootstrap 模板；由 WP-16 合入根配置。

## 验收与证据

完整 Given/When 与证据要求见 [验收目录](../acceptance-catalog.json)。本包负责自己的适用断言；跨包场景由 owner 提供材料，集成人最终执行。

| ID | 层次 | 必须观察到的结果 |
| --- | --- | --- |
| CORE-01 | core | 144-test baseline 保留且无 DSH 宿主依赖；MIT/来源齐全 |
| DATA-01 | schema | 单一来源、身份/版本/required criteria 完整，旧消费者行为明确 |
