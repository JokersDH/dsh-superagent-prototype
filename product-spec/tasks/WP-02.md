## 实施步骤

1. 选择性提取领域 SQL/索引/事务行为，去除旧 Store 应用迁移与 DSH imports；新产品独立 state/schema。
2. 实现嵌套 savepoint、rollback、afterCommit；核心变更、产品索引、effect、receipt、event 在同事务。
3. 保留 Effects 算法并加入未知原生发送的分类接线；文本 Outbox 与 AnswerDelivery 分离。
4. 独占管理迁移号与所有产品表；提供 real-binding crash harness、完整性检查、backup/restore 和 orphan/retention ports。

## 验收与证据

完整 Given/When 与证据要求见 [验收目录](../acceptance-catalog.json)。本包负责自己的适用断言；跨包场景由 owner 提供材料，集成人最终执行。

| ID | 层次 | 必须观察到的结果 |
| --- | --- | --- |
| DATA-01 | schema | 单一来源、身份/版本/required criteria 完整，旧消费者行为明确 |
| DATA-02 | storage | core、索引、receipt、effect、event 全部提交或全部回滚 |
| DATA-03 | storage | 语义相同去重，冲突拒绝；不重复派工/答案/事实 |
| DATA-04 | storage | 使用同连接 savepoint；回滚 effect 不外发，afterCommit 仅正确提交触发 |
| DATA-05 | storage | 引用不指向半文件，活跃/备份引用不被删，orphan 宽限期清理 |
| DATA-06 | storage | 拒绝不一致，不误开旧应用 DB，不跳过失败迁移 |
| DATA-07 | integration | 答案先持久且至多一条合法投递通路，恢复后逐 target 状态准确 |
| DATA-08 | integration | 一致 cursor、无事件缺口；Work 执行投影可由核心和物理事实重建 |
| REL-01 | fault | 未提交不半接单，已提交继续原 effect 而非重建工作 |
| REL-02 | fault | 可证 not_sent 才重发；未知先 reconcile，不无界付费重试 |
| REL-03 | fault | 唯一 writer；PID/租约过期不冒充死亡证明 |
| OPS-03 | release | 一致快照完整、integrity/foreign_key 通过、不自动重发业务 |
