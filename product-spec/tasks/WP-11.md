## 实施步骤

1. 先以固定 scenarios 做真实可操作 app shell：主对话为首页，紧凑列表、项目/回复锚点和空状态。
2. 实现澄清/权限/认证/主观验收不同表单；答案已记录/写出/未知按 target 呈现，不自行改变 phase。
3. 实现候选/验证/交付、修订/停止中、过期按钮、登录/能力/漂移状态；关闭重开和 SSE gap 恢复。
4. Playwright 覆盖桌面/窄屏、键盘/焦点、长文本/错误，验证模型离线仍能查询回答停止；不在 UI 写厂商分支。

## 验收与证据

完整 Given/When 与证据要求见 [验收目录](../acceptance-catalog.json)。本包负责自己的适用断言；跨包场景由 owner 提供材料，集成人最终执行。

| ID | 层次 | 必须观察到的结果 |
| --- | --- | --- |
| AC-UX-01 | e2e | 建议不被自动全量执行，委托可形成目标/范围 |
| AC-UX-02 | e2e | 仍可确定性完成，不依赖模型 |
| AC-UX-03 | e2e | WorkId 稳定，phase 来自核心/物理事实 |
| AC-UX-04 | e2e | 不串台，归属可见且可纠正 |
| AC-UX-05 | e2e | 业务答案有条件共享，原生授权逐请求；表单无品牌解析 |
| AC-UX-06 | e2e | 不假报已切换/已停；pause 不假装暂停当前工具 |
| AC-UX-07 | e2e | 显示未通过，过期候选不能交付完成 |
| AC-UX-08 | e2e | 正常交付；不要求全库导入/实验设置 |
| AC-UX-09 | e2e | 分别呈现，不用一个绿灯替代，不让不合格目标 begin |
| AC-UX-10 | e2e | 恢复主对话和结果，旧答案不唤醒停止工作 |

| AC-UX-12 | e2e | 无重叠溢出，焦点不被抢，屏幕阅读不重复播报 |
