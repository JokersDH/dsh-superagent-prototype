- source 与 installed、normal 与 recovered 分开，source checkout 不补 immutable package 缺 entry。
- 一次消费者不能拼多段不同 Work/run 的数据；原 IDs/source/实际方法链清楚。

### H2 真正可接受状态与完整交付操作消费者

- 候选先出现、动作延迟出现必须继续等，不是立即失败/跳过，更不能提前 accept。
- 机器 FAIL、blocked、human criterion、scope/contract 变化和 UNKNOWN writer 各保留真实原因。
- 只有动作门满足才显式发送完整 CandidateRef；stale candidate negative 必须真的运行，未运行写 NOT_TESTED。
- installedAcceptGateObserved 必须记录 inclusion/原 Work/candidate 身份，不只记录数组存在。
- 观察 ready→review→accept 的真实时间，未量到的人审耗时不编造，不把点击记录当质量收益。
- 同源 artifact/location/download、delivered 与非空重开结果一起核对。
- 使用已有真实受控项目/注册 check，不把固定假候选或直写 accepted 当原用户动作。

明确区分门已观察、accept已发送、recorded和delivered，缺某一步就保留该步未达。

### H5 Field diagnostics、source 与支持材料闭合

完整成果：同事遇到启动/执行/等待/交付问题时，能拿到准确、脱敏、可复现的支持材料。

- 记录 exact source/build/tar/consumer hash、mode/operation、health/selection/配置来源，必要字段不得猜测。

- UNKNOWN/DEGRADED/FAIL与 exit语义匹配，未测/缺失字段不默认 PASS，不删错误材料。
- 不收无关凭据、用户私有 DB或全局进程列表；源路径/认证头脱敏，读取不启动工作/模型。
- 同时验证错误主体/错source/缺entry/旧服务/权限不足的合法对照，owner能按材料复现。
