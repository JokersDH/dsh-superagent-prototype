# 主线：主对话工作台与确定性产品集成

基线 `c3f018e`。主线继续 primary checkout，先读本轮 README 与路线图。保留用户未跟踪的 `ARCHITECTURE-NOTES.zh-CN.md`；不改 A/B/C/D/E checkout。拥有 console、contracts、application/questions、coordinator、root 配置/锁和共享文档；B 的 Runner/Driver 区域暂停并发编辑，A 唯一拥有生产迁移，E 的验收目录不并发写。

## M1 稳定 interface 与 UI 基线

- 按用户确认的主对话中心、石墨导航/白色对话/青绿强调建立工作台设计约定与状态地图；保留现有真实工作行为。
- 公共资源先明确会话目录、项目版本设置、上下文来源、提案、决定、执行诊断和可用恢复动作的读取/命令语义，消费现有 schema，按兼容方式扩展并生成；不凭 UI 需求打破 frozen Runner/data wire。
- 与 A/B/C/D 一次写明 port、事务归属、错误、版本和验收边界。root lock 只有主线生成，迁移仅 A 提交。先发布可供其它人消费的 checkpoint，然后继续后续阶段。

## M2 完成可操作的新工作台

主对话为中心，服务端会话/项目目录、当前任务侧栏、集中问题、交付/diff/检查证据可顺畅展开；任务状态和按钮来自实际 backend projection。以紧凑导航、清楚信息层级、固定工具尺寸和渐进披露呈现桌面式体验，不让技术日志占主入口。

普通聊天、工作补充和新委托保持明确区别；新提案经用户确认才生成命令。处理长中文/路径、离线、慢响应、空列表、权限/环境错误、提交中/重复点击、过期候选和消息恢复，失败保留输入和上下文身份。新 UI 不展示伪指标、不把 fixture 当生产、不放不可用的假功能。

验证桌面/笔记本/窄屏、键盘与焦点、对话滚动与面板尺寸；按设计 skill 的有界轮次检查并一批修复，不无限视觉打磨。E 的产品验收由 E 独立维护，主线可运行已提交工具并报告结果。

## M3 接通日常工作流和可恢复错误

- 消费 A 的会话目录/搜索归档、项目设置版本和上下文读索引；当前 Work/合同/检查定义保持冻结，新设置仅作用于新授权。
- 把验证、环境、执行与恢复错误投影成稳定诊断和允许动作，提供“重新检查/重新准备/核对或停止”等已具正确语义的入口。不能因点击恢复重发未知 begin/deliver/answer。
- 验证意图失败不只无限后台重试；区分暂时失败、需要用户修正与不可自动恢复，保留证据与原实体。原生 stopped 与物理停止分别呈现。
- 消费 B 的 Runtime 控制/问题/恢复检查点，使用其公开 port，不在 coordinator 复制一套 Driver 或资源证明。

验收：断开重连、失效问题、旧设置、缺依赖、环境漂移和检查失败都有准确状态；机器失败不能接受，未知 writer 不启动第二写入者，重试结果有可核对回执。

## M4 接通上下文、提案和明确决定

消费 C 的有界、带来源的读上下文与提案/决定规则，复用现有 reasoner/model provider 及受控请求，不自建通用 LLM tool loop。模型只产生经 parser 校验的提案；主线在确认时重新检查 actor、project/scope、合同版本及资源屏障。

明确决定可记录、撤销、查看来源和适用范围，撤销或过期内容不进入后续上下文；不把用户改目标自动推成长期偏好。自动规则推广和研究性自我进化仍关闭。

验收默认用 mock SDK：提示注入、伪造工具/权限、跨项目上下文、旧提案、重复确认、撤销后重开均不能产生越权执行或重复计费。
